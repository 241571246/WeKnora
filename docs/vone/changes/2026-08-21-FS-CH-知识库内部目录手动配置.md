## 登记目的

记录知识库内部文档目录从“随文件上传路径派生”扩展为“可由用户独立创建和维护”的变更诉求，供后续产品、技术、数据迁移和发布影响评估使用。本次只登记，不进入详细设计、任务拆解、开发、测试或发布。

## 用户表述

> 当前知识库里面的目录不能独立手动创建，需要支持自定义目录手动配置，而不是只能通过上传知识库文件夹形成目录。当前先登记，后续评估后再决定是否开发。

## 当前基线

- 知识库内部目录由文档记录的 `folder_path` 聚合生成，没有独立目录实体。
- 移动或上传文档到新路径可以形成目录；目录内最后一个文档移走后，该目录会从目录树消失。
- 当前目录树支持浏览和重命名；独立创建、移动、排序和删除空目录不属于已批准基线。
- `REQ-2026-001` 明确将“持久化没有任何文件的知识库内部空文件夹”列为非本期范围。
- 本变更只涉及知识库内部文档目录，不等同于工作空间中的知识库集合/项目树，也不改变知识库 ACL 基线。

## 变更前后对照

| 维度 | 当前基线 | 变更候选 | 当前结论 |
| --- | --- | --- | --- |
| 目录来源 | 从文档 `folder_path` 动态派生 | 允许先创建目录，再上传或移动文档 | 待评估 |
| 空目录 | 不持久化，无法长期显示 | 刷新和重新登录后仍保留 | 待评估 |
| 目录操作 | 浏览、重命名、随文档移动形成路径 | 候选支持新建根/子目录、重命名、移动、排序、删除空目录 | 待确认范围 |
| 上传行为 | 上传本地文件夹时保留相对路径 | 保留原行为，并允许选择已手工创建的目标目录 | 候选兼容策略 |
| 文档处理 | `folder_path` 仅用于展示和导航 | 目录调整原则上不触发重新解析、分块或向量化 | 候选兼容策略 |
| 权限 | 使用 `kb.folder.manage` 管理目录和移动文件 | 默认继续复用该能力，不新增文件夹级 ACL | 待确认 |

## 初步技术建议（未批准）

1. 新增 VONE 独立目录表，持久化知识库内部目录节点；不修改已发布的上游 `000079_knowledge_folder_path` 迁移。
2. 继续保留 `knowledges.folder_path` 作为现有文档归类和查询兼容字段，避免立即引入大范围 `folder_id` 改造。
3. 迁移时根据存量 `folder_path` 回填现有目录及其祖先节点。
4. 目录树查询合并独立目录节点与文档数量统计，使空目录也能返回且计数为 `0`。
5. 上传文件夹、上传到指定目录和移动文档时自动确保对应目录节点存在，保持老调用方兼容。
6. 目录重命名或移动应在同一事务中同步更新目录子树和相关文档路径；不重新解析或生成向量。
7. 普通删除默认只允许空目录；存在文档或子目录时拒绝级联删除。

以上仅为登记阶段的可行性建议，不构成架构决策或开发授权。

## 初步影响半径

- 数据库：可能新增 VONE 目录表、唯一约束、索引、存量路径回填及 PostgreSQL/SQLite 对应迁移。
- 后端：目录类型、Repository、Service、Handler、Route、事务、审计和权限测试。
- API：目录树响应可能加目录 ID；候选新增创建、移动/排序和删除目录接口，并保留现有 GET、文档移动及重命名兼容路径。
- 前端：`KnowledgeBase.vue`、`KbFolderTree.vue`、目录 API、目录树 helper、上传目标目录、文档移动选择器、i18n 和定向测试。
- 权限：默认复用 `kb.folder.manage`；是否需要文件夹级权限不在当前候选范围。
- 发布：涉及数据库、App 和前端组合发布，不能按纯前端调整处理。
- 回滚：常规回滚应保留新增目录数据；旧版本可能暂时看不到空目录，但已有文档的 `folder_path` 仍需正常工作。

## 兼容性分类

- 类型：加性数据库变更 + 修改型目录行为。
- 老数据：需要无损回填，不能改变现有文档、切片、向量和文件存储关系。
- 老调用方：现有上传、目录查询、文档移动和重命名接口应继续工作。
- 上游升级：定制数据结构应进入独立 VONE 迁移序列，和上游知识库目录实现保持薄接入。

## 待评估事项

- [ ] 是否必须支持持久化空目录；本登记默认“需要”，最终由产品评估确认。
- [ ] 首期操作范围是否包含新建、重命名、移动、排序和删除空目录全部能力。
- [ ] 目录删除是否严格限制为空节点，是否允许批量删除空子树。
- [ ] 目录排序采用名称排序、数字前缀排序还是人工拖拽排序。
- [ ] 是否继续沿用最大 16 层、单段 128 字符、完整路径 1024 字符限制。
- [ ] 是否明确排除文件夹级 ACL，仅复用 `kb.folder.manage`。
- [ ] PostgreSQL 与 SQLite 存量回填、升级和回滚方案是否可接受。
- [ ] 目标 Release、优先级、Owner、实施 Task、工期和独立 QA 安排。

## 候选验收方向（未批准）

- 可以在没有任何文档的知识库中创建多级目录，刷新和重新登录后仍存在。
- 可以把单文件、批量文件和本地文件夹上传到已创建目录。
- 文档全部移走后目录不会自动消失，只有用户明确删除空目录才移除。
- 重命名或移动目录后，子目录和相关文档路径一致，且不触发重新解析或向量化。
- 同级重名、非法字符、超深层级、跨知识库和跨工作空间操作被后端拒绝。
- 没有 `kb.folder.manage` 的用户只能浏览，无权创建、移动、重命名或删除目录。
- 存量上传目录和现有 API 行为保持兼容。
