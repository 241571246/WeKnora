# VONE知识库 UI 主题包定制需求

> 需求状态：首个定制版本 v0.1 已接入 Vue 生产代码，构建与视觉验收进行中。
> 中文产品名称：`VONE知识库`。
> 英文产品名称：`Vone Knowledge`。
> 版权信息：`@vonechina 2026`。
> 核心原则：继续使用 WeKnora 核心，只建立低侵入、可升级的品牌与主题扩展层。

## 1. 背景

VONE知识库需要拥有独立的品牌视觉，但仍需持续吸收腾讯 WeKnora 的功能更新。直接大范围修改上游页面、菜单、路由和请求层会显著增加升级冲突，因此本需求采用“主题包 + 品牌配置 + 少量稳定接入点”的模式。

当前 v0.7.2 前端为 Vue 3 + Vite + Pinia + TDesign，已经具备 light/dark/system 主题机制，主题变量集中在 `frontend/src/assets/theme/theme.css`，适合作为扩展入口。

## 2. 目标

- 将中文产品展示名称统一为 `VONE知识库`，英文名称统一为 `Vone Knowledge`；
- 支持 Vone Logo、favicon、登录页品牌和菜单品牌；
- 在不重写业务页面的前提下提供浅色、深色和跟随系统主题；
- 形成独立主题包，升级上游时尽量只处理一个接入点；
- 前端定制镜像与官方 App/Docreader 镜像可独立升级和回滚。

## 3. 范围

### 3.1 纳入范围

- 品牌配置：产品名、短名称、Logo、深色 Logo、favicon、版权信息；
- 设计令牌：主色、辅助色、成功/警告/错误色、文字、背景、边框、圆角、阴影、间距和字体；
- TDesign 变量覆盖；
- 登录页和全局菜单的品牌展示；
- 浏览器标题与基础元信息；
- 浅色、深色、跟随系统三种主题；
- 独立前端镜像标签、视觉回归截图和升级检查清单。

### 3.2 不纳入范围

- 不修改后端 API 契约；
- 不修改认证、Token 刷新和空间隔离逻辑；
- 不重写 Pinia Store、路由体系和统一请求层；
- 不改变知识库、智能体、聊天、模型管理等核心业务行为；
- 不在本需求中重构上游所有页面；
- 不移除上游 MIT License 和第三方许可声明。

## 4. 建议的主题包结构

实施时新增独立目录，避免把 Vone 样式散落到上游组件中：

```text
frontend/src/customizations/vone/
├── brand.ts
├── index.ts
├── tokens.css
├── light.css
├── dark.css
├── tdesign-overrides.css
└── assets/
    ├── logo.png
    ├── logo-dark.png
    └── favicon.ico
```

只允许在上游入口保留少量接入：

- `frontend/src/main.ts`：导入 Vone 主题入口；
- 登录页：读取统一品牌配置，不再硬编码 Logo/名称；
- 菜单组件：读取同一品牌配置；
- HTML/Vite 元信息：设置标题和 favicon。

不得在每个业务页面单独引入 Vone CSS。

## 5. 兼容与升级分级

| 定制类型 | 是否建议 | 升级风险 |
| --- | --- | --- |
| CSS 变量、TDesign Token 覆盖 | 建议 | 低 |
| 独立 Logo、favicon、标题配置 | 建议 | 低 |
| 登录页/菜单的统一品牌组件 | 建议，控制改动行数 | 中低 |
| 新增独立 Vone 页面或组件 | 可做，避免改上游同名文件 | 中 |
| 修改路由、权限、请求和 Store | 原则上不做 | 高 |
| 大范围重排上游核心页面 DOM | 原则上不做 | 高 |
| 直接复制整套上游前端长期分叉 | 不建议 | 极高 |

## 6. 功能要求

### FR-01 品牌配置单一来源

产品名、Logo 路径、版权信息只能在一个品牌配置模块中定义。登录页、菜单和浏览器标题不得分别硬编码。

### FR-02 主题模式

保留上游 light/dark/system 行为，Vone 主题只覆盖设计令牌，不另建相互冲突的主题状态管理。

### FR-03 主题包开关

通过构建期配置选择 `upstream` 或 `vone` 主题。关闭 Vone 主题后应能恢复上游默认视觉，不影响核心功能。

### FR-04 资产替换

Logo 与 favicon 使用 Vone 自有资产；资产缺失时应有明确构建失败或默认回退，不出现空白图片。

### FR-05 独立镜像

UI 交付只构建 `vone/weknora-ui:<upstream-version>-vone.<revision>`，不因纯视觉变更重建 App、Docreader、PostgreSQL 或 Redis。

## 7. 非功能要求

- 不把 API Key、内部地址或部署秘密打入前端构建物；
- 主题切换不刷新页面，且不产生明显闪烁；
- 关键页面在常用桌面宽度下无布局溢出；
- 浅色和深色模式满足基本对比度与可读性；
- Vone 接入点应集中、可搜索、可从 Git diff 快速识别；
- 新增依赖必须说明必要性，主题定制优先不增加运行时依赖。

## 8. 验收标准

1. 登录页、菜单、浏览器标题一致显示 `VONE知识库` / `Vone Knowledge`；
2. Logo、favicon 在浅色和深色模式下清晰可见；
3. light/dark/system 三种模式均可正确切换并持久化；
4. 知识库、智能体、聊天、模型管理和设置页面功能无回归；
5. 前端 API 路径、JWT 刷新、`X-Tenant-ID` 和 SSE 行为无变化；
6. 仅重建前端镜像即可发布和回滚主题；
7. 与目标上游 tag 合并后，Vone 定制冲突集中在主题入口和品牌接入点；
8. 形成登录页、首页、知识库、聊天、设置页的浅色/深色视觉回归截图；
9. License 与第三方声明仍保留。

## 9. 实施阶段

### 阶段 1：品牌输入冻结

确认 Logo、favicon、主色、字体、版权文案、登录页风格和是否保留 WeKnora 联合标识。

### 阶段 2：主题基础设施

建立 `customizations/vone`、品牌配置和设计令牌，只接入 `main.ts`，不改业务页面。

### 阶段 3：品牌接入

将登录页、菜单和 HTML 元信息的硬编码品牌替换为统一配置。

### 阶段 4：视觉校准

按页面优先级逐页校准，修改应优先落在主题变量和独立覆盖层；确需改组件 DOM 时单独评审升级成本。

### 阶段 5：回归与升级演练

执行前端构建、浏览器真实交互、关键流程回归、视觉截图对比，并选择一个更新的上游 tag 做合并演练。
